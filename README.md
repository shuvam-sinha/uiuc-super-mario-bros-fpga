# Mario FPGA

A side-scrolling Super Mario Bros. clone built on a Xilinx Spartan-7 (RealDigital Urbana board), combining a custom SystemVerilog game engine with a MicroBlaze soft-core C firmware layer.

- Tile-based scrolling background, sprite rendering, HUD/score overlay, and 1-bit square-wave audio output (3.5mm jack)
- Custom AXI4-Lite IP core (`mario_controller_v1_0`) driven by a MicroBlaze soft processor
- 8.8 fixed-point physics
- USB keyboard input handled by the MicroBlaze firmware

Built in Vivado 2022.2 and Vitis.

## Repo structure

```
hardware/
├── constrs/          # Pin constraints (.xdc)
├── bd/                # Vivado block design (MicroBlaze + peripherals)
├── src/               # Top-level SystemVerilog game logic
└── ip_repo/
    └── mario_controller_1_0/   # Custom AXI4-Lite IP core (packaged)
        ├── hdl/       # IP core SystemVerilog source
        └── src/       # COE memory-initialization files (tile/sprite ROMs)
software/
└── src/               # MicroBlaze C firmware (Vitis application)
    └── lw_usb/        # USB HID driver (keyboard input)
```

## Prerequisites

- Vivado 2022.2 (or compatible)
- Vitis (matching version)
- RealDigital Urbana board (Spartan-7) — or adjust `hardware/constrs/mb_usb_hdmi_top.xdc` for your target board

## Building the hardware

1. Create a new Vivado project targeting the Spartan-7 part used on the RealDigital Urbana board.
2. Add `hardware/ip_repo/` as an IP repository (**Settings → IP → Repository**) so Vivado picks up `mario_controller_1_0`.
3. Add the block design source: `hardware/bd/mb_block.bd`. Let Vivado regenerate the block design output products.
4. Add the top-level SystemVerilog sources from `hardware/src/`.
5. Add `hardware/constrs/mb_usb_hdmi_top.xdc` as a constraints source.
6. Run synthesis, implementation, and generate the bitstream.

**Note on constraints:** `mb_usb_hdmi_top.xdc` was reused as-is from an earlier, separate lab project rather than authored fresh for this one. If you're building for different hardware, or the pin mapping doesn't match your board revision, you'll need to update it before synthesis will produce correct I/O.

## Building the software

1. In Vitis, create a new platform project from the exported hardware (`.xsa`) generated by Vivado after implementation.
2. Create a new application project targeting that platform, using the "Empty Application" template.
3. Import the contents of `software/src/` (including the `lw_usb/` subfolder) into the application's `src/` directory.
4. Build the application and program the board (Program FPGA, then Run/Debug the application).

## Notes

- `color_mapper.sv` (top-level) and `Color_Mapper.sv` (inside the IP core) are two distinct files at different paths, differing only by case — this reflects the original project structure and both are required as-is.
- `component.xml` is Vivado-generated IP metadata required for Vivado to recognize `mario_controller_1_0` as a packaged IP core on import.
